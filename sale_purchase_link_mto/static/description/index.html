🔗 Sale Purchase Link MTO Enhancement

Módulo Backend para vincular líneas de venta con líneas de compra en procesos Make-to-Order

📋 Descripción del Problema

En Odoo estándar, el campo sale_line_id en purchase.order.line solo se rellena en casos específicos:

  • ✅ Servicios subcontratados (módulo sale_purchase)
  • ✅ Dropshipping directo
  • ❌ MTO estándar con purchase_stock ← Este módulo lo soluciona
⚠️ Importante: Este módulo es 100% backend. No modifica interfaces de usuario, solo proporciona funcionalidad programática para desarrolladores y reportes.

⚙️ Instalación Paso a Paso

1. Prerrequisitos

# Módulos requeridos (se instalan automáticamente): - sale_stock - purchase_stock - sale_purchase_stock

2. Instalación del módulo

# 1. Copiar a addons cp -r sale_purchase_link_mto /path/to/odoo/addons/ # 2. Reiniciar Odoo sudo systemctl restart odoo # 3. Actualizar lista de apps en Odoo UI Apps → Update Apps List # 4. Buscar e instalar Search: "Sale Purchase Link MTO Enhancement" → Install

3. Verificación de instalación

✅ Módulo instalado correctamente si:
• No hay errores en log de Odoo
• Aparece en Apps instaladas
• Los campos sale_line_id y customer_id están disponibles programáticamente

🚀 Configuración y Uso

Configuración del Producto MTO

1. Ir a Inventario → Productos → [Tu Producto]
2. Pestaña "Inventario":
• ✅ Ruta: "Make To Order (MTO)"
• ✅ Ruta: "Buy" (Compra)

3. Pestaña "Compra":
• ✅ Configurar al menos un proveedor
• ✅ Precio y tiempo de entrega

Flujo de funcionamiento

Sale Order → Stock Move → Procurement → Stock Rule → Purchase Order
↓              ↓                ↓                ↓                ↓
sale_line_id propagado automáticamente + customer_id calculado

Ejemplo de uso programático

# Crear orden de venta con producto MTO sale_order = env['sale.order'].create({ 'partner_id': customer.id, 'order_line': [(0, 0, { 'product_id': mto_product.id, 'product_uom_qty': 5.0 })] }) # Confirmar orden → Genera automáticamente compra vinculada sale_order.action_confirm() # Acceder a la vinculación desde código po_lines = env['purchase.order.line'].search([ ('sale_line_id', '!=', False) ]) for po_line in po_lines: print(f"PO: {po_line.order_id.name}") print(f"SO: {po_line.sale_line_id.order_id.name}") print(f"Cliente: {po_line.customer_id.name}") print("---")

📊 Campos Disponibles

purchase.order.line

  • sale_line_id: Many2one → sale.order.line (línea de venta original)
  • customer_id: Many2one → res.partner (cliente calculado automáticamente)

Ejemplos de consultas

# Buscar compras vinculadas a ventas linked_purchases = env['purchase.order.line'].search([ ('sale_line_id', '!=', False) ]) # Buscar por cliente específico customer_purchases = env['purchase.order.line'].search([ ('customer_id', '=', customer_id) ]) # Análisis de márgenes SO vs PO for line in linked_purchases: sale_price = line.sale_line_id.price_unit purchase_price = line.price_unit margin = sale_price - purchase_price print(f"Margen: {margin:.2f}")

🔧 Casos de Uso

  • 📈 Reportes personalizados: Trazabilidad completa SO → PO
  • 💰 Análisis de márgenes: Comparación automática precios venta vs compra
  • 👥 Segmentación por cliente: Compras agrupadas por cliente final
  • 🔄 Automatizaciones: Workflows que requieren vinculación SO-PO
  • 📡 APIs e integraciones: Datos vinculados para sistemas externos
  • 📋 Auditorías: Seguimiento completo de transacciones

⚠️ Limitaciones y Notas

  • Solo Backend: No hay vistas UI adicionales
  • Solo MTO + Buy: Requiere ambas rutas configuradas
  • Productos con proveedor: Debe tener vendor configurado
  • Sin dropshipping: Para dropshipping usar módulos estándar
